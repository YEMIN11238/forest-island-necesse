## 1 产品目标与本次取舍

要做的是“玩家和少数有个性、有共同经历的 AI 伙伴一起生存和建设营地”。伙伴既能真正帮忙，也有自己的生活；玩家离开营地探索时，需要相信伙伴能够在授权范围内继续工作，遇到困难会明确说明，遭遇危险能及时应对。

下一阶段最重要的三件事：

1. 让画面在保留现有光影、风动和细节的条件下流畅，解决“素材在动，但整帧不顺”的问题。
2. 将“执行一次原生作业”补齐为“完成一个可核实的玩家目标”，包括数量、目标箱子、加工、送达、打断和恢复。
3. 将“玩家问一句、模型答一句”补齐为“会生活、能主动判断、记得实际经历”的两名核心伙伴，同时控制费用和权限。

采用一个 Java 运行世界和一个权威库存系统。继续复用 Necesse 的移动、寻路、战斗、采集、配方、库存、聚落、需求、倒地和保存；GitHub 代码补任务控制、记忆、绘制效率、内容工具及验证。星露谷用于条件日程、个人事件和生活反馈的设计参考，C# 运行系统不直接混入当前 Java 内核。

本版完成标准是第 12 节列出的玩家流程和故障场景通过。编译成功、生成了图片、收到模型回复、原版内部存在接口，均不能单独代表一项功能完成。

## 2 当前版本到底有什么、还缺什么

### 2.1 基于源码和运行记录的现状

| 领域 | 已实现或已有证据 | 缺口与实际影响 |
| --- | --- | --- |
| 世界 | 192×160 有限世界，两种预设，种子/生成器/内容版本与指纹，地表和洞穴合法往返 | 地形内容仍少，生态差异和阶段目标不足；地图引导及内容升级恢复尚不完整 |
| 伙伴身份 | 稳定 companionId 对应原生居民；可保存身份、任务和真实事件 | 伙伴初始化就在营地，尚无完整招募事件、个人目标和深入关系内容 |
| 基础任务 | 跟随、守卫、回家、工作、采收一处、搬运一批及暂停/取消；复用原生作业 | 一批工作不等于指定数量和指定仓库交付；加工、建设备料、完整救援任务未闭环 |
| 模型 | Java 17 异步 HTTP 接官方 DeepSeek；文字意图最多提出一项动作 | 尚无连续任务规划、自主思考、长期对话摘要；只接入 API 不会自动获得这些能力 |
| 模型验证 | 3 次真实请求验证跟随、取消、聊天不改变任务；实际原生状态匹配 | 不能由此推导复杂任务成功率、长期人格一致性或自主行为已完成 |
| 记忆 | AI Town 排序公式已有 Java 移植；保存真实事件，当前最多 64 条 | 缺少长期事件档案、对话摘要、知情范围细化和带来源反思；目前没有语义向量检索 |
| 生存与救援 | 原生饥饿、休息、战斗、倒地和复活入口可复用 | 本作的救援材料引导、护送、恢复期和阶段性存档验证不完整 |
| 动植物 | 原生兔/羊/鸡及僵尸/骷髅等生成，存在数量上限和营地安全距离 | 不是已完成本作生态；缺栖息地行为、清晰威胁差异、内容平衡与完整原创动画 |
| 建筑 | 已有结构实例、门、窗灯和床位等锚点 | 多栋自建住宅、任意合规墙体的屋顶和照明适配仍需完成 |
| 素材 | 两名伙伴 24 张运行纹理；四向站立/行走与基础工作、搬运、倒地、睡眠姿势 | 单张工作姿势不是完整动作；动物、怪物及部分角色状态仍缺，生成图也未必已绑定 |
| 画面 | 风动、像素处理、局部光、地面/海面投影已接入；白天地面和树冠分开调色 | 大森林性能明显不达标；不能靠继续加灯、加植物、加模型请求掩盖 |
| 保存 | 新世界与重载、箱子、制作结果、身份、事件、取消任务及洞穴往返有验证 | 多步骤任务中途退出、救援各阶段、旧档升级、异常恢复和长期索引一致性未形成完整套件 |

当前 AI 动作白名单为 FOLLOW、GUARD、HOME、WORK、CANCEL、HARVEST、HAUL；GUARD 只接受这次请求提供的玩家位置。任务层的暂停/继续不等于模型已经能正确理解所有自然语言变体。林业原生适配存在，也不能提前等同于“20 个木材入指定箱子”已实现。

### 2.2 最先解决的硬问题：帧时间

最近大森林 30 秒无截图记录：平均 **27.38 fps**，p95 **67.78 ms**，p99 **120.57 ms**，13 帧超过 100 ms。记录包含渲染、交换与等待的完整帧间隔，不是纯 CPU 或 GPU 渲染时间。[原始记录](../mosslume/validation/refactor-0.4-r1/forest-performance.json)

旧视觉岛的六秒约 55.6 fps 与这次世界规模、视野和测量条件不同，不能直接算成优化前后提升率。已有缓存修复解决了已定位的哈希查找和临时分配，但没有证据证明整体帧率已改善。[实施记录](IMPLEMENTATION-0.4-r1.md)

因此下一阶段先处理绘制提交、分配和完整帧耗时，再开放更多同时行动的实体。保留植被密度、8 光源预算和现有阴影质量作为对照条件；任何质量调整要单独记录，不能悄悄降画质后宣称性能问题解决。

| [Generative Agents / plan.py](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/plan.py)，Apache-2.0 | 需要细化日计划、任务分解和事件响应规则 | 参考/选择性移植规则，不启动 Python/Django 第二世界，也不照搬研究模拟中的密集模型调用 |

LangChain4j 的 TokenWindowChatMemory 解决近期消息窗口，不等于长期人生记忆。SQLite 的 FTS5 也不等于中文语义检索；DeepSeek 对话接口不应被假设为已经提供向量接口。上述区别决定了哪些模块仍需本作适配。

Necesse 恢复代码不是这些开源组件的一部分。当前方案服务现有私人原型，公开发布或独立商业发行前，需要另行确定内核运行与分发授权；把素材和标题替换掉不会自动改变这一边界。

### 5.2 线程与写入规则

- 原生模拟线程拥有实体、库存、任务最终状态、关系、进度及权威事件写入权。
- 渲染线程只消费场景快照和已上传资源，不进行 HTTP、SQL、内容磁盘扫描或模型等待。
- 模型线程读取经过知情范围筛选的不可变快照，返回建议；不能直接调用原生实体方法。
- 索引/摘要工作线程串行处理每名伙伴的有序事件；落库前检查世界会话与存档代次。
- 原生完成、取消和失败回调转成一次性回执；重复回调不能重复计数或发奖励。

## 6 F01 画面与流畅度优化

### 6.1 问题与保留项

当前树冠已使用连续时间和 8 段变形网格，但植物绘制仍有逐物件 GL11 立即模式提交。高密度场景中，单棵摇动连续不代表整帧连续。要同时检查 CPU 提交、状态切换、临时分配、驱动等待和后处理，不能先假定换风公式或换图片就会解决。

当前 Mac 为 Apple M5，运行包内 Java 17 x86_64/Rosetta，图形路径是 OpenGL 2.1、GLSL 1.20。本阶段不得以 GL3.3 实例化、计算着色器或更换整套引擎作为默认前提。切换 ARM JVM/渲染后端是独立兼容性实验，只有全依赖、画面、输入和保存验证后才能考虑替换。

必须保留：

- 像素内部清晰，边缘采用现有亚像素覆盖；不加整屏模糊或双线性放大掩盖抖动。
- 树根固定，树冠连续轻摆，不整棵左右平移；角色、树、建筑和物件遮挡顺序正确。
- 白天地面与树冠有色差，夜间周围暗、火源附近暖且亮；窗灯、火焰自发光可辨。
- 树木与物品阴影脚点不漂移；岸线按真实陆水边界向海面投影；多光源能互相补光。
- 海面深浅、颜色和流动随时间变化；荧光点缓升、淡入淡出；原有自然道路不过度矩形化。

### 6.2 技术步骤

1. 固定种子、时间、相机、植被、灯光数和窗口尺寸，采集完整帧时间、JFR 和 async-profiler；分开记录有截图和无截图场景。
2. 先将植物 8 段条带写入复用的交错顶点缓冲，以兼容 GL15 VBO 的方式提交。风场时间、根权重、原生颜色和像素覆盖公式保持一致。
3. 参照 libGDX SpriteBatch 的缓存和 flush 机制，合并相邻且渲染状态一致的物件。分段树需要自己的网格索引，不能直接按普通四顶点精灵提交。
4. 在保持原有 Y 排序的前提下，再试离线图集减少纹理切换。不可为了批次少而把所有同纹理树重排到人物前面。
5. 将 phase、脚点、尺寸、材质等按物件写入顶点/批次数据；旧 GLSL 不支持的能力使用兼容路径，不能无声退回错误画面。
6. 阴影接收器已存在逐灯批处理，先测量其 CPU/GPU 同步成本再改。保留每光源 union mask、海面裁剪及根部/风动同源；不能重复造一套影子系统。
7. 视野变化才重建可见对象列表；移除静态场景的逐帧对象创建。维护资源销毁、窗口缩放、地图切换和 GL 状态恢复。
8. 在上述工作后再决定是否需要调整离屏缓冲大小或光源选择，任何视觉成本取舍都记录前后对照。

### 6.3 建议性能验收目标

以下是目标，不是当前成绩。以同一台机器、包内运行时、单游戏窗口、60 fps 上限、逻辑 1200×900/实际帧缓冲 2400×1800 为基准；窗口或渲染倍率变化要另报。

| 指标 | 建议门槛 |
| --- | --- |
| 样本 | 预热至少 30 秒，固定路线每场景记录 180 秒；截图/编码不进入性能样本 |
| 场景 | 代表性密林白天、8 光源预算内的夜间海岸、两伙伴工作并发生战斗 |
| 完整帧 | 60 fps 上限下平均 ≥57 fps，p95 ≤20 ms，p99 ≤33.3 ms，超过 50 ms 的帧 <0.5% |
| 后台模型 | 网络进行时不出现与等待响应同步的模拟/绘制停顿；无 render-thread HTTP/SQL |
| 稳定性 | 连续移动、开关 UI、地图往返后，堆内存和显存资源不持续累积 |
| 视觉 | 固定风时间与同相机对照无根漂、穿插、阴影断层、贴图白边或夜景变亮 |

若门槛未过，报告明确瓶颈和仍差的指标，保持 G0 未通过。不同质量/窗口配置的数据分栏，不能只报最好的短样本。完成目标所需次数由新证据和变更决定，不无理由反复全量测试。

## 7 F02–F04 连续任务、仓库与建设协作

### 7.1 玩家看到的行为

以“去授权林区收集 20 个木材，放进我选中的箱子”为主验收用例：

1. 选定伙伴、目标箱子、材料和数量，明确采集范围；文字与按钮生成同一个 TaskSpec。
2. 先检查权限、工具、原生林业区、目标箱子和可达性。信息不足才询问玩家；已有指向和默认工作区就直接执行。
3. 执行找资源→原生采集→拾取→搬运→存放→核实入箱。显示“已送达 8/20”，而非仅统计挥斧或地上掉落。
4. 箱满、道路堵、工具缺、资源不足分别显示原因和下一步；玩家取消立即停止后续步骤，已送达部分保留。
5. 两人或玩家同时工作时，不重复预约材料，不把玩家自己存入的木材记成伙伴贡献。
6. 伙伴遭遇危险时优先避险；危险结束后按任务恢复策略重新验证目标，不能盲目沿旧路径继续。

“做 5 份食物放进公共食物箱”和“为已确认的建筑补齐材料”使用相同编排层，底层调用原生配方、扣料和放置作业。AI 可以准备和执行允许的施工任务，不能自行在营地新增一栋玩家没批准的大楼。

### 7.2 拟新增数据契约

| 结构 | 必要字段与用途 |
| --- | --- |
| TaskSpec | taskId、来源、companionId、目标种类、材料 ID、数量、授权区域、目标引用、优先级、完成条件 |
| TaskPlan | 有上限的步骤、依赖、当前步、累计回执；先支持线性计划和前置条件，不先造通用工作流平台 |
| TargetRef | worldId、levelId、稳定目标 UUID、坐标、对象实例代次；箱子被拆后重建不能默认仍是同一目标 |
| WorkReceipt | 原生作业/转移操作 ID、实际产出或转移量、源/目标、时间、结果与可重放核对信息 |
| PermissionProfile | 可进区域、可用设施/仓库、物品保留量、保护树、允许自动工作类型 |
| TaskBlock | 明确原因码、玩家可读说明、是否可自动重试、下一检查条件 |
| WorldEvent | 唯一 eventId、世界/会话代次、实体、事件类型、真实结果、知情人及来源 |

状态使用 proposed→validating→queued→running→succeeded，并支持 blocked、paused、failed、cancelled。危险/倒地属于中断原因及伙伴生命状态，不再建立一套冲突的血量状态机。

计划长度建议最多 8 步，同一阻碍最多自动重规划 2 次，之后等待条件变化或玩家处理。这些是初始调度参数，不是上游项目自带或当前已经实现的默认值。

### 7.3 原生复用与开源移植的分工

- 原生 HumanMob、JobSequence、SingleJobSequence、ForestryLevelJob、HarvestCropLevelJob、HarvestFruitLevelJob、HaulFromLevelJob、StorePickupItemLevelJob 负责真实作业和物品流转。
- 加工评估 CraftSettlementRecipeActiveJob，建设评估 PlaceObjectLevelJob 及原生建造预约；能力、配方、设施与失败回调验证后才加入白名单。
- Mindcraft ActionManager 用于执行/停止/恢复/超时和循环检测的组织方式，替换其 Minecraft 动作与进程退出逻辑。
- 本作必须实现 TaskSpec 到原生作业的映射、目标稳定引用、数量结算及权限校验；没有可直接覆盖这些 Necesse 对象的通用 GitHub 项目。

原生工作有 5–10 秒初始冷却，当前已做有上限的排队重试。新编排器保留这种等待语义，不能在第一帧没有作业时就报告失败，也不能无限重试。

玩家在权限面板划定采集/工作范围后，由适配层同步建立或关联原生工作区，避免要求玩家理解原版内部的林业作业区才能下令。能力需要的原生区域尚未成功建立时，该任务不能假装进入运行态。TaskSpec 还要区分“新采集材料”和“从已有公共库存调拨”，防止把已经存在的材料当作本次新采集成果。

### 7.4 数量、库存和保存的正确性

原生采集可能一株/一棵产出超过剩余需求。允许多采出的材料继续作为真实库存或掉落存在，但完成数量只统计送入指定目标的本任务材料，不删除“多余物”来制造精确结果。

每次原生取放生成一次回执，任务状态依据实际转移核实；不能按仓库总量增量直接归功，也不维护一份 AI 自己扣减的影子库存。仓库保留量先通过原生可用量/预约约束；原生无法原子表达的规则，要在同一模拟线程内校验并执行，测试竞争情况。

中途保存使用原生权威库存和任务检查点；加载后先核对实体、已提交回执和目标代次，再决定继续或标为待处理。原生世界、区域和玩家文件不是已证明的跨文件原子事务。需增加完整检查点备份和恢复验证；遇到无法可靠判定的异常写入，停任务、说明恢复方案或回退最近完整备份，不能猜测补发材料。

### 7.5 验收重点

- 同一命令从按钮和文字进入后，原生行为、物品和完成条件一致。
- 20 木材入指定箱子、5 份食品加工送达、建设备料三种流程有真实证据。
- 箱满/箱子拆除/道路封闭/工具缺失分别可解释；不重复扣料、不空报完成。
- 执行中取消、暂停、危险打断、重启恢复均保留真实已完成量，释放原生预约。
- 两伙伴同时取用与玩家竞争时守住保留量，无物品复制或重复回执。
- 原生作业不支持的任务明确拒绝或提出替代，不能让模型编造“已经完成”。

## 8 F05–F09 伙伴生活、自主行为、记忆与救援

### 8.1 从“员工”变成两名长期伙伴

小禾、林叔沿用暂定身份，先做两名完整角色。角色擅长和偏好是本版建议内容，后续可改配置：

| 伙伴 | 初始倾向 | 玩家能观察到的差异 |
| --- | --- | --- |
| 小禾 | 偏种植、采集，关注食物和附近植物 | 会优先处理成熟作物，记得玩家帮忙建立食物供给的经历，提醒依据实际储备 |
| 林叔 | 偏建造、加工，关注住所和工具 | 会在授权下检查工作区和照明，提出补料建议，交流时更关注营地条件 |

复用原生 SettlerPersonality、需求、生活质量、吃饭、睡眠、工作与战斗字段。本作角色定义提供偏好、表达约束和个人事件条件，不再另造一套重复的饥饿或生命数值。

增加一次可理解的加入事件：玩家在可达区域帮助伙伴完成一个实际需求，伙伴加入后分配床位和权限。招募事件以稳定 ID 保存，只能结算一次。新手或测试档可单独跳过，不把“开局已送两人和大量材料”作为正式流程。

日常活动使用条件日程：有住处才回对应床位，有工作台才排相关工作；饥饿、危险和玩家指令可以打断。世界暂停/退出时停止本地模拟和自动模型触发。未加载区域沿原生模拟规则处理，不凭模型对白结算远处生产。

### 8.2 三层 AI：及时反应、日常决策、语言与高层选择

| 层级 | 负责什么 | 技术与触发 | 是否需要模型 |
| --- | --- | --- | --- |
| 反应层 | 避险、战斗、寻路、倒地、停手、释放预约 | 原生 HumanAI/JobSequence，按原生模拟更新 | 不需要 |
| 生活/工作层 | 吃饭、睡眠、按权限补料、常规收获、选择可做的营地工作 | 条件日程与有限候选任务评分；事件或定时低频检查 | 不需要 |
| 表达/规划层 | 理解文字、解释困难、共同经历对白、有限建议、选择高层目标 | DeepSeek，经预算与状态校验的事件调度 | 需要时调用 |

移植 Mindcraft self_prompter 的暂停/停止/恢复和无进展停止语义，参考 modes 的本地优先级；不照搬其持续循环问模型和默认 2 秒冷却。日程分解参考 Generative Agents，但首版以可检查的本地规则生成候选，模型只在候选和权限边界内选择。

### 8.3 主动行为的触发与权限

首批主动事件限定为食物将不足、夜间照明/燃料不足、成熟作物待收、有人倒地、已接受任务遇阻，以及一个阶段目标完成后的有限交流。

建议初始参数：

- 自动高层决策每伙伴最短间隔 60 秒，同类事件合并；本地危险反应即时执行，不等待这个间隔。
- 整个世界自动模型请求最多 30 次/小时，包含自动提醒与其摘要等附加请求；仍受现有每日总次数和费用上限约束。
- 每伙伴最多一个在途模型决策；自动建议未处理前不重复刷屏。玩家新指令优先，取消旧自动计划的过期回包。
- 不因普通库存波动逐件发消息。阈值采用进入/退出不同界限，避免状态在临界值反复触发。
- 长时间离线或错误后进入退避，继续本地工作；服务恢复不补发积压过期请求。

这些频率是待试玩调整的设计起点。玩家手动交流不受自动冷却限制，但仍计入统一费用和总次数。

权限在工作区界面一次配置，日常执行不逐件弹确认。可设置活动区、允许仓库、口粮/种子/稀有材料保留量、保护植物及允许任务。补火、采收、搬运等已授权小事可自动做；拆房、消耗保留资源、离开授权区的远征和替玩家招募等必须有明确玩家指令。

优先级默认：危险/倒地 → 玩家紧急停止或救援 → 玩家已确认任务 → 基本需求 → 已授权日常工作 → 社交休闲。具体原生避险机制保持最高即时响应；饥饿等严重程度可提升为紧急需求。恢复被打断任务前重新核对权限与目标。

### 8.4 记忆：从 64 条事件到可溯源的长期经历

复用 AI Town 的 rememberConversation 与 reflectOnMemories 组织方式，增加以下四层。不同层的内容不能混写：

| 层 | 内容 | 权威性和写入方式 |
| --- | --- | --- |
| 世界事件档案 | 采集送达、一起建造、遇险救援、招募等真实事件 | 原生回执生成，保存唯一来源 ID；关键事件不受近期 64 条缓存淘汰影响 |
| 知识与承诺 | 亲眼看到、玩家告知、他人转述、待履行承诺 | 保存知情人、来源、确认程度；“玩家说山后有矿”不等于游戏证实那里有矿 |
| 对话档案/摘要 | 近期交流与压缩摘要 | 对话是说过的话；摘要必须引用原对话/事件 ID，不能作为物品、伤势或任务完成证据 |
| 个人反思 | “那次救援让我更信任玩家”等看法 | 模型可生成表达，但事实引用必须可核对；关系变化仍由游戏规则结算 |

近期检索继续用相关性、重要性和时效排序。先增加角色/事件/地点/主题标签与中文词项或双字片段检索，再评估多语言向量召回；不因为 AI Town 调用 embeddings 就强制部署向量库。

长期数据保存在版本化原生扩展档案中。若引入 SQLite JDBC，它只保存派生索引和水位 eventId，不作第二个权威世界；中文检索需显式分词/片段策略，不能声称启用 FTS5 就有中文语义理解。少量角色数据在实测确有需要前，可以使用内存索引。

摘要、反思按事件批量和重要性触发，不每条事件调用模型。重要性先由事件规则给值；救援和共同建造可保留，普通重复搬运合并统计。压缩失败保留原始数据与旧摘要，不能用空结果覆盖。删除/重置记忆和加载更早存档时，索引随存档代次重建，不能泄露“未来”经历。

建议首轮验证：让伙伴经历一次救援、一次共同建造和一次明确承诺；再完成至少 100 条普通事件并重启。伙伴仍能正确提及重要经历，对没见过的事件允许说不知道，不把计划当已完成事实。

### 8.5 救援与恢复

复用原生倒地/复活和物品掉落。新增引导与连续性，不复制原生生命状态机。

1. 第一次可能遇险前，玩家能获得救治方式，基础救治材料有可达来源。
2. 倒地发出清晰提示，地图显示救援位置和已知路径，模型失联不影响救援入口。
3. 现场救治调用原生物品与复活条件；缺材料说明具体缺什么，不在聊天里“治疗成功”。
4. 复活后核对 companionId、原生实体、住所、权限、关系和事件；不通过重新生成同名人物代替。
5. 提供护送回营指令，进入简单恢复期，恢复期工作强度与生命条件按规则处理。
6. 原生倒地掉出的工作物品仍在真实物品系统中；任务根据实际库存重新核算，不能重发一套。

分别在倒地、救治中、复活后、护送中保存并重启，验证人、物、关系、任务和床位一致。被救者与救援者均只能记住实际参与或获知的过程。

### 8.6 模型接入、失败与费用

保留已有 Java 17 HttpClient、minimal-json 和 ModelProvider。DeepSeek 的 Tool Calls 可以描述工具，但实际执行函数仍由应用提供，因此必须保留本作白名单、原生能力和结果核验。[官方工具调用说明](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)

模型建议只携带任务意图。世界/伙伴身份、requestId、状态版本、任务 revision 和会话 epoch 均由游戏绑定；模型不能自己指定可信身份。取消、暂停、读档、切换世界、改变伙伴及退出后，过期动作、摘要、反思均不得落档。

| 失败情况 | 游戏行为 |
| --- | --- |
| 断网/超时/429/5xx | 保持原生工作，说明本次交流未成功；有限退避，不无限重试 |
| 返回格式错误/未知动作 | 拒绝执行，记录脱敏原因，保留上一任务；不自动猜一个破坏性动作 |
| 信息不足 | 提出一次具体澄清，确认后再提交；不在后台反复调用直到“猜对” |
| 服务返回后目标已变 | 丢弃过期建议，UI 显示当前真实任务；不扣材料、不增加经历 |
| 预算不足 | 自动与手动模型入口说明额度状态；任务按钮和原生生活继续运行 |
| 请求结果未知 | 保留保守费用预约，不将取消当作免费或自动重试理由 |

当前默认每日 200 次请求、5 元估算预约上限，额度文件跨重启保持。后续对白、规划、摘要、反思和重试全部走同一个账本，不新增旁路 HTTP。开发用例默认不联网，不能为回归测试反复消耗用户余额。

费用示例只用于设计限额：截至 2026-10-23，Flash 缓存未命中输入为 1–2 元/百万 tokens，输出为 4–8 元/百万 tokens，随时段变化。假设全世界所有模型功能合计 50 次请求/小时，每次输入 4000、输出 500 tokens，则约 0.30–0.60 元/小时；每天 2 小时、30 天约 18–36 元。这里包含所有请求类型，忽略缓存折扣，不是账号实际账单或承诺。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

已有 3 次实测合计输入 2364、输出 238 tokens，按高峰价上估约 0.006632 元，只证明那三次简单交互成本。复杂规划可能多次请求，不能把该样本当长期平均。

## 9 F10–F13 世界、生存、生态与建设

### 9.1 保留生成底座，完善内容与可达性

WorldPreset 决定有限世界形态，BiomeDefinition 决定生态内容，RuleSet 决定生存规则。保留现有 192×160 和两个预设作为首轮覆盖，不为了“无限”重写生成器。

生成分阶段：边界/陆水 → 生态分布 → 安全出生/营地/洞穴/招募锚点 → 连通道路 → 资源 → 动植物和装饰。FastNoiseLite 继续提供噪声，本作校验必须确保出生点、食物、木石、救援材料、伙伴和阶段目标可达。对失败种子进行有上限的布局重选，最终失败给出提示，不把玩家送进死局。

普通道路连接实际入口和活动点，沿地形转折，使用现有连续自然边缘；模板里不能画宽大矩形泥块代替道路。岸线、土地侧面、影子接收共用真实陆水边界。

迷雾/标记继续复用原生地图；增加营地、住所、已知入口、任务目标和救援标记。未发现区域不能因为 AI 提示而全图解锁。跨图和复活仍只允许本作注册的地表/洞穴，不再意外回原版其他世界。

### 9.2 内容定义与 Tiled 模板

把现有 properties/CSV 的内容入口升级到版本化定义，迁移时保留 v1 加载器和原内容指纹。JSON Schema 负责字段和类型，构建期还校验原生 ID、资源文件、能力、引用、模板出入口及配方循环等语义问题。

Tiled 只编辑营地、遗迹、资源点等小模板，不替代种子世界。首版导入器只支持明确子集：正交有限地图、未压缩 JSON 图块/对象层、命名锚点、显式 nativeId 和自定义属性。不支持的压缩、旋转、外部引用或无限图层应在构建期报错，不能静默读错。

模板声明占地、入口、床位、工作点、灯、碰撞、屋顶组、道路连接点和允许地形。导入后生成原生对象和同源 StructureInstance，不能只有好看的底图却没有可交互设施。工具导出和原生保存仍是两件事。

### 9.3 生存与生态首轮内容

| 内容 | 先复用什么 | 本作要补什么 | 验收 |
| --- | --- | --- | --- |
| 食物/燃料/作物 | 原生生长、烹饪、饥饿与燃料 | 出生物资有限、再生/替代来源、伙伴可用保留量 | 有准备与消耗，不靠无限赠送燃料维持 |
| 两类动物 | 原生逃跑、采食/生产、活动 AI 中兼容的原型 | 明确栖息地、时段、密度、原创外观和至少两种可辨行为 | 不是静态摆件；不无限积累 |
| 两类普通敌人 | 原生近战/远程等已有行为与掉落 | 攻击提示、出现条件、夜间风险、营地安全距离 | 玩家能辨认威胁并准备；不直接刷在床上 |
| 采集资源 | 原生树、果实、矿物、掉落 | 分区分布、再生与保护树规则、外观比例 | 基础资源可持续，合作采集不毁掉营地装饰 |
| 三段进度 | 原生配方与建筑、真实事件 | 安营、稳定供给、准备并共同探索洞穴的目标 | 目标可追踪，奖励/解锁只依据实际事件 |

当前 rabbit/sheep/chicken、zombie/skeleton 只是可用原型清单；具体首轮物种、名称、美术与数值以新内容表为准。禁止把同一行为换两张图就说已完成生态差异。

### 9.4 多住宅、屋顶与灯光

继续使用原生墙、门、床和聚落居住规则。StructureInstance 统一提供建筑占地、入口、脚点、床位、屋顶组及光源位置；不能在角色、门和灯三个类里分别写房子坐标。

先支持两栋可入住的合规住宅、一处公共工作区及储物/烹饪/照明设施。屋顶按约定墙体布局和模块素材拼接，近人物时按规则遮挡或淡出；一张房屋 PNG 无法正确覆盖所有任意形状，因此首轮明确支持的屋顶模块和建筑形状。

移墙、拆门、换窗、移动床或熄火后，碰撞、住所、灯源和阴影注册随实例更新。建筑拆除触发关联任务失效，不让伙伴继续向已拆的工作台送材料。

## 10 F14 素材与界面补齐

### 10.1 把素材交付从“有图”改成“动作已接入”

建立一份 AssetManifest，分别记录 concept/generated、exported、bound、runtime-verified 四个状态。每个角色/物件有来源、帧尺寸、方向、帧数、脚点、碰撞/交互锚点、材质、阴影掩码、允许回退和实际绑定入口。

现有两伙伴以 64×64 帧、脚点约 (32,52)、身体约 32 源像素、运行放大 2 倍为比例起点，逐物件校准。不能为了填满格子把人物或某株植物放大一倍，也不能混入一套明显不同像素密度的角色。

| 素材组 | 已有基础 | 本阶段补齐 | 优先次序 |
| --- | --- | --- | --- |
| 小禾、林叔 | 四向站/走；单张基础工作、搬运、倒地、睡眠 | 四向工具动作、搬运连续姿态、攻击/受击、坐姿、床上遮罩与恢复姿态 | 任务/生活/救援所需状态优先 |
| 玩家 | 原创身体和原生工具层可用 | 持工具、攻击、受击和环境交互的一致比例与方向 | 与伙伴同一比例检验 |
| 首轮两类动物 | 原生行为可用 | 站/走/进食或生产/逃跑/受伤的必要方向与状态 | 生态接入前 |
| 首轮两类敌人 | 原生战斗可用 | 移动、攻击前摇/攻击、受击/倒下，必要方向 | 战斗可读性优先 |
| 建筑/设施 | 房屋、木柴、火焰、工作台等已有图 | 模块屋顶/墙角、门窗开闭、床椅、燃料/工作状态、损坏或不可用提示 | 多建筑闭环优先 |
| 植物/地形 | 多批源图和部分运行绑定 | 新生态成套草地/树/灌木/小花、岸线与侧面，统一比例和配色 | 先用现有合格图，再补确实缺图 |
| UI/图标 | 现有面板与物品图标 | 任务/需求/救援/地图标记和状态图标，统一清晰像素边缘 | 先可用，再统一装饰 |

逐帧预览后使用 LibreSprite 修整边缘和动作，沿用现有 Pillow/最近邻导出脚本。若引入图集，先禁止旋转和破坏脚点的裁边；确需裁边则保存原始尺寸、offset 和 pivot，并同时给角色、风动及影子使用。不能只调整主画面 UV，忘记阴影掩码。

风动是运行 shader 的职责，火焰使用现有循环帧，烟/荧光由粒子控制；不需要给每丛灌木生成大量近似帧。补素材时先列清运行缺口，避免继续大量生成却没有接入入口。

### 10.2 玩家界面

任务面板显示执行者、目标、已送达量/总量、当前步骤、阻碍和操作按钮。伙伴页显示需求、住所、权限、关系变化来源和近期共同经历；地图页承接营地/任务/救援定位。

模型等待显示可取消的交流状态，原生任务进度继续更新。玩家看到的是“箱子已满，已送达 12/20”，不是 request epoch、token、回调或内部异常堆栈。费用/模型配置放设置页，与伙伴口吻分开。

使用原生实际输入走通点击、拖放、焦点、打字、切换角色、关闭窗口和恢复。当前探针调用同一后台队列，只能证明执行链，不能冒充物理鼠标点击验证。

## 11 F15–F16 保存、扩展接口与兼容性

### 11.1 存档结构和升级

原生 World/Level/Player 保存继续为权威。扩展数据升级 CompanionWorldData schema 1→2，至少包含身份、任务检查点、权限、角色生活/关系、事实事件、对话档案/摘要、进度和存档代次。具体存储大小先测量，不能将全部长文本每帧全量复制。

建议升级流程：识别版本→备份最近完整档→按版本迁移→核对原生实体和引用→重建索引→保存新版本。每步失败保持旧档可恢复。未知更高版本拒绝写入，不能以默认值覆盖。自动测试使用副本，不操作日常个人档。

加载时：

1. 校验世界、生成器、内容快照与资产/定义引用。
2. 将伙伴 UUID 与实际原生居民重新关联；不按名字猜身份。
3. 恢复世界/库存后核对目标、预约、任务回执和实际物品；需要人工处理的歧义任务先暂停。
4. 取消存档前的全部在途 HTTP；新的会话 epoch 让旧回包无效。
5. 根据事件水位和 saveGeneration 重建/修复记忆索引，回档后删除未来派生数据。
6. 验证床位、营地名、已完成招募/救援/解锁及地图发现没有重置。

旧区域不重新生成，旧世界继续锁定创建时的生成与内容版本。普通增加地形默认用于新世界；未来扩张旧世界使用独立 WorldExpansionPlan，本阶段只定义边界，不承诺已有扩张功能。

### 11.2 预留接口与“以后加地图要不要改功能”

| 扩展点 | 通过配置/素材可加入的内容 | 仍需要代码的情况 |
| --- | --- | --- |
| WorldPreset / BiomeDefinition | 已有地形、噪声、生成规则、生态/颜色/声音/模板的组合 | 新的世界拓扑、特殊加载方式或跨海机制 |
| RuleSet / RuleModule | 消耗、产率、威胁、惩罚等已有规则参数 | 温度、冻伤、氧气、船只、离线生产等全新机制 |
| EntityDefinition / NativeArchetype | 已有动物/敌人行为原型的新外观、数值和生成条件 | 全新移动/战斗/群体行为 |
| ActionCapability / NativeJobAdapter | 已有动作的目标、材料、范围和完成条件 | 新工作类型及其原生执行/中断/回执适配 |
| StructureDefinition / SceneComponent | 已支持设施、门窗、屋顶模块、灯和碰撞组合 | 新种类互动、特殊物理或垂直层 |

扩展验收样例：在不新增“如果地形名等于某某”核心分支的条件下，用定义与素材加入一块湿草甸、一种树变体和一个已有工作能力的新设施；生成、任务、地图、风动光影和保存都正常。它证明通用入口可用，不等于雪地机制、划船或任意未来玩法已经实现。

默认先运行纯本地/固定响应测试，再在独立原生 QA 存档验证行为。付费模型检查单独启用、限定数量和金额。已有成功证据在代码未变化且风险未增加时可复用；新增复杂行为和保存路径需要新增证据。

### 12.1 模型用例和真实性检查

promptfoo 用于维护首轮约 40 条中文用例，覆盖明确指令、别称、数量、选中目标、信息不足、权限拒绝、任务取消、普通聊天、未知经历和恶意越权文本。这个数量是建议测试规模，不是现有已通过数量。

固定响应测试负责状态、取消和错误路径；模型抽样负责自然语言理解。对所有抽样的已接受任务要求原生执行边界成立，非法世界写入为零。语义理解率、澄清率、虚构完成、任务完成率和响应延迟分别报告；不能用“JSON 正确率”代替任务完成率，也不能为了通过测试把不同合理澄清都判错。

任务完成由游戏状态与库存核对，不让另一个 LLM 只看对白判断成功。默认关闭模型裁判、云端上传与自动付费重跑。主动性是否烦人、角色是否可信仍需真实试玩反馈，不能由单元测试代替。

### 12.2 文档、素材和版本完成定义

每项交付同时具备：实现与来源记录、必要内容/素材、原生运行证据、保存兼容结果、已知限制和回退办法。素材仅生成或仅导出都不是完成；人工输入无法验证时必须明确留下未验收项。

发布说明分别列“已实现”“仅接入接口”“待验证”“未实现”。本版不再用整体完成百分比替代逐项证据。

## 16 追加需求：更多有记忆的角色、有层次的世界与完整战斗

追加日期：2026-10-23。以下来自用户最新反馈，是新增设计与待实现内容，不表示当前预览已经具备。现阶段仍先通过 G0；不把扩充角色、生成图片和战斗机制混进性能对照。本文前面的两名伙伴是首轮验收范围，不是正式世界的角色数量上限。

### 16.1 AI 角色的规模和玩家交互

建议内容目标为 2–4 名核心伙伴，另有普通居民、商人、流浪者与事件人物。先让已有两人完成生活、任务和记忆闭环，再加入第三、第四人。普通居民首轮可按 8–16 人的内容容量设计，但这是待性能与试玩验证的容量目标，不是当前地图的已实现数量。远处居民用低频模拟；活跃模型请求由全局队列控制，初始并发上限 1–2，不按居民总数同时调用。

| 角色层级 | 玩家能怎么交流 | AI 的作用 | 本地系统的职责 |
| --- | --- | --- | --- |
| 核心伙伴 | 附近直接对话、伙伴面板、指向地点/物品后提出请求 | 个性表达、理解需求、询问缺失信息、回忆、提出计划、协商或拒绝 | 寻路、工作、生活、危险反应、权限、材料和任务结果核实 |
| 普通居民 | 闲聊、询问近况、简单委托，熟识后可招募 | 交谈时按身份、已知事件和关系回应；重要经历可保存 | 日程、生产、交易价格和库存；不持续进行模型思考 |
| 商人和访客 | 询价、打听、交换信息、接委托 | 有限信息与动机表达，基于真实条件提出事件 | 交易校验、物品交付、任务触发和去留条件 |
| 敌对智慧角色 | 少数剧情人物可以警告、谈判或投降 | 低频动机与对话；可提出经规则验证的战斗阶段意图 | 命中、冷却、仇恨、移动、技能阶段及伤害均实时本地执行 |
| 动物和普通怪物 | 驯养、喂食、观察行为、战斗反馈 | 通常不调用语言模型；重要命名动物可记录经历 | 栖息、觅食、逃跑、警戒、攻击和繁殖等行为树 |

右键或互动键应能直接打开角色对话，避免只能从隐藏面板找到 AI。对话框同时显示身份、当前意图、任务进展和可点击的真实目标；闲聊不更换任务。含糊的“去帮忙”先澄清；可明确定位的指令转为 TaskSpec，由原生适配执行。世界中观察到的人物动作才是执行证据，模型的口头承诺不能标成完成。

体验样例：玩家说“天黑前把这些木头搬进这个箱子，晚上别去森林”。系统结合选中物、剩余时间、背包和保留量提出可核实的搬运任务，并记录临时安全约定；不能完成时说明真实原因。伙伴曾被玩家救援，之后会提及该事件，并在信任、求助或冒险选择上体现受规则约束的变化。此样例依赖 G1–G3，当前版本不宣称已支持整句任务。

### 16.2 性格、记忆和自主性如何落到行为

角色状态拆为四类：稳定人格与价值倾向、缓慢变化的关系/习惯、短期情绪与需要、具有时间和来源的事件/对话记忆。一次聊天可以形成偏好、待确认约定或情绪影响；长期性格变化须由持续经历与事件规则累计，不能靠一句“你现在勇敢”覆盖角色设定。

记录采用稳定事件 ID、参与者、目击/听说、事实引用、所在存档分支和世界时间。重要救援、失约、赠礼、合作、冲突长期保存；普通对话按段摘要并保留来源。模型可以提出记忆摘要与关系变化解释，本地规则核实后保存。错过的事件可以不知道、听说的不自动成为事实；旧档不能带入未来记忆。

自主性从本地需要和事件开始：饥饿吃饭、到夜晚回营、危险撤退不等模型；库存低、任务受阻、重要冲突时才按额度请求计划。玩家可以授权工作范围、禁止消耗某些材料、要求跟随、暂停或取消。显示伙伴的简短意图和真实阻碍即可，不展示模型内部思维。

AI 也可以用于营地之外的世界内容，但须共享同一调度与额度：居民之间围绕真实事件交谈并形成有来源的传闻；任务系统把实际缺粮、失踪、威胁或设施损坏转成有角色动机的委托；探索事件给出与种子世界现有地点匹配的线索；营地日志整理当天共同经历。模型只提出对白、动机和已定义事件/任务的参数，奖励、敌人强度、地点存在性和资源交付仍由游戏核实。首轮不让模型逐格生成地图，也不以自动生成无穷文本替代可玩的内容。

技术上沿用 AI Town 的记忆排序，后续有选择移植有来源的对话摘要/反思；沿用 Mindcraft 的动作生命周期、打断和停止循环语义。它们不能直接替代本作的 Java 世界、NPC 动作和库存系统。现有采用状态仍以第 4 节及研究清单为准，不把“参考过”写成“已经接好”。

### 16.3 地图层次不是单独加碰撞盒

目标是同一美术尺度下的草甸、林缘、高台、崖壁、台阶、海滩和遗迹过渡，并有营地、生产区、林中空地等可辨认地点。先制作一个包含营地、两级高台、上下通路、海岸与遗迹的代表片区，确认清晰度、遮挡和可达性，再用于种子世界的模板组合。

当前内核主要是二维格子。首轮采用有高度感的 2D 台地：地面层、立面层、植物/建筑层、前景遮挡层配套，崖缘阻挡，楼梯和坡道连通，角色脚底排序，岸边和高台阴影随光变化。上下桥面在同一格重叠、自由跳跃和真正多层战斗属于另一个机制阶段，不能仅增加贴图或碰撞就宣布支持。

新增内容契约候选为 TerrainDefinition、ElevationBand、CliffEdge、TransitionRule、Passage、PrefabAnchor。以原生可走格和边界为权威，在模板导入时生成阻挡与通路；探索地图、生成连通性、伙伴路径、敌人追踪和存档须读同一份结果。Tiled 只作为模板编辑和导出工具，FastNoiseLite 负责宏观分布；两者均不会自动补齐合法台地和游戏可达性。

### 16.4 素材缺口和制作顺序

以下按素材族估计，连接组合和最终帧数在代表片区验收后锁定。先确认格子尺度、角色比例、透视、像素密度、昼夜调色和光源方向。光照不烘死进底图；风动植物保持根部锚点，建筑碰撞与阴影轮廓另有定义。生成图必须经过切图、像素清理、连接检查和运行绑定，不能整张概念图直接充当地图块。

| 批次 | 素材族 | 必须包含的变体和状态 | 用途 |
| --- | --- | --- | --- |
| A 地形层次 | 草甸、湿土、泥路、砂地、碎石、岩地、苔藓 | 同尺度平铺、转角/内角/边缘、窄路与柔和过渡 | 消除大平面和矩形拼块感 |
| A 地形层次 | 土崖、岩崖、草崖、崖顶、立面阴影 | 四向边缘、凹凸角、两级高度、可拼接立面 | 高台、沟壑与岛岸厚度 |
| A 地形层次 | 台阶、坡道、木桥、栏杆 | 四向连接、入口出口、前后遮挡拆层 | 可辨认的通路与空间关系 |
| B 营地与建筑 | 帐篷、两种小屋、工坊、仓库、废墟 | 墙/门/窗/屋顶拆层、开关状态、损坏状态、脚底锚点 | 不同功能区、探索据点和建设反馈 |
| B 材质与生活 | 木板、石砖、泥墙、屋瓦、围栏、家具 | 可拼接块、工作台使用状态、箱子开合、床与生活道具 | 支撑建造和 NPC 可见生活 |
| C 角色与生态 | 核心伙伴变体、访客、商人，两类动物 | 四向站走、工作/搬运/休息/受伤；动物移动/进食/警戒 | 角色差异和生态行为 |
| D 战斗 | 两类普通怪、一个精英/首领的候选外观 | 四向移动、预备、攻击、命中、倒地及投射物 | 支撑明确不同的攻击模式 |
| D 特效 | 挥砍、突刺、箭/弹、落点提示、冲击/受击/击退、死亡粒子 | 原地特效与弹体分开、明确帧时长和伤害生效点 | 读得清、躲得开的战斗反馈 |

先完成 A 的一套可拼接台地，B 的一套营地建筑和 C 的已有两人缺失动作；D 先做两种攻击闭环需要的最小图组。其余逐批补，避免先生成几十张无法统一比例或无法使用的图。

### 16.5 怪物和攻击模式

复用 Necesse 原生的寻路、碰撞、仇恨、弹体、伤害、击退、冷却和掉落；不能只换外观后把原生全部敌人算成本作内容。首轮做近战扑击者和远程投射者：前者有蓄力、冲刺、结束僵直，后者有瞄准预警、投射物和重新站位。精英候选在这两类完成后再增加召唤或范围攻击，避免首轮同时引入多个无法验收的系统。

AttackDefinition 统一保存 windup/active/recovery、范围或弹体 ID、伤害触发点、可打断条件、预警和特效锚点。动画帧与伤害事件由同一时间轴驱动；特效本身不造成额外伤害。伙伴应能预警、撤退、救援或按授权协战，禁止模型直接填写任意伤害、坐标瞬移或每帧决定闪避。

### 16.6 追加验收与阶段归属

新增 AC20：两种身份的角色可从场景直接交谈；聊天不丢失现有任务，含糊请求会澄清。AC21：保存/重载后能回忆有来源的共同经历，关系变化会影响至少一个真实选择；普通聊天不会无限改写稳定人格。AC22：代表台地上下入口可通行、崖缘不能穿越，伙伴和怪物寻路一致；前景遮挡、脚底排序及昼夜投影正确。AC23：两类敌人具有可识别预警、命中窗口与恢复期，攻击/特效/伤害一致，并正确保存或重建状态。

这些要求分别进入 G1–G3 的任务/交流/记忆，以及 G4 的世界/素材/战斗。G0 尚未通过时只整理定义与素材规格，不扩大活跃实体数量或自动模型调用。正式验收还需在新增代表片区重新确认帧时间；原有密林场景性能通过不能替代新场景验收。
