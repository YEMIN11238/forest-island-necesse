# Mosslume 0.5.0 世界、交互与场景修正

日期：2026-10-24。对应 [统一实施方案](PLAN-WORLD-NPC-VISUALS-2026-10-24.md)。这份记录区分实际接入、原生检查与尚未完成的效果，不能代替完整 PRD 验收。

## 运行入口与存档

独立应用为 `/Users/zhangjunhao/Applications/Mosslume World Preview.app`，普通资料目录为 `~/Library/Application Support/Mosslume-World-Preview`。原来的 Companions Preview 应用、资料目录和正在运行的进程不自动替换。

新建世界默认“连续荒野”，生成/内容版本为 v4。原生按 16×16 区域生成、请求、卸载与保存；起点为局部规划的海岸营地，外侧继续程序生成。旧 v1–v3 世界沿用原内容与布局，不原地改绘。海岸布局属于新 v4 世界；已有测试档不会自动变成新的起点。

## 世界与可靠性

- 新增 ContinuousSurfaceLevel / ContinuousCaveLevel、MosslumeContinuousStack、ContinuousWorldLayout 和区域内容接入，复用原生 BiomeGeneratorStack、区域网络与存档。没有新增另一套地图引擎，也不分配无限大的二维数组。
- 七类地形依据种子和世界坐标采样；起始营地、道路与建筑只覆盖有限局部区域。FastNoiseLite 继续用于噪声，不能代替区域流式加载。
- 修复运行内核中的区域数据快取失效：原生 removeRegion 卸载后可能保留 lastRegion 快取，随后把已 dispose 的区域返回。适配层在卸载时失效同一快取，不修改恢复内核文件。
- 开发诊断记录区域请求、生成、接收/应用、服务端心跳和保存耗时，使用有界缓冲。QA 另有客户端看守：服务端心跳超过 20 秒未更新时导出本进程 Java 线程和 JFR，标记失败并退出隔离测试，避免把仍在渲染当作世界正常。
- 集成 e 实际复现了服务端冻结。保存的 JFR 中 2,950 个执行采样有 2,856 个在 Server Thread，绝大多数落在 ItemFinder 的取食搜索。恢复内核的字节码确认：每轮算出 prev()，但 finally 没有把 next 赋回 current；无效、被过滤或预留失败的记录会永久重复。NativeStorageFinderRepair 已在适配层修正三个库存搜索入口，补游标推进与结构性遍历上限，保留原生库存、预留和接受语义。证据在 `mosslume/validation/world-visuals-r6/server-freeze-before.json` 及 `itemfinder-runtime-before-javap.txt`。不能据此断言所有历史冻结都来自同一处。

## 攻击与角色动画

玩家及三套居民外观新增四方向、六帧攻击身体，共 96 个姿势，空手身体和原生武器分层。攻击方向、身体帧、武器轨迹共享真实原生攻击进度，取实际正在出手的物品，避免切换快捷栏后画错工具。

待机只变形胸肩以上部分，鞋底和世界脚点固定；已有行走序列继续按真实移动距离选帧。只有静态侧身素材的商人行走仍是局部步态补间，不能称为全新逐帧行走素材。低频眨眼和部分职业独有动作仍待补。

自定义怪物改为前摇、一次生效、收势；近战命中与远程发射在服务端执行。对象死亡/消失、无效目标和前摇受击会取消，停止动画通过原生能力同步。生效时再校验距离、目标权限和遮挡；服务端跨过整个生效窗口时不会补一个迟到伤害。上下方向不再套侧面攻击图，但多数怪物仍缺完整四向逐帧攻击素材。

libGDX 只采用 Animation 的进度选帧与边界处理思路，没有嵌入第二套引擎。来源、许可和适配说明在 `third-party/libgdx-render/ANIMATION-PORT.md`。

美术生成使用 imagegen，以现有主角/农夫/木匠/商人作为参考，提示词要求四行方向、六列空手攻击姿势、固定鞋底、透明背景。原图和逐张提示词/来源见 `mosslume/art/characters-r6/manifest.json` 与 `sources/`；`mosslume/scripts/export_character_actions.py` 仅机械裁切、统一同一方向尺度、按鞋底导出。运行条带在 `mod/resources/mosslume/players/` 与 `residents/`。

## 交谈和人口

新增服务端 ConversationLease，连接原生交互登记与 HumanInteractingAINode。交谈期间停步、面对玩家；任务保留，结束、超距、切图、危险等路径释放。模型回复和寻路仍走原有身份/请求票据约束。

开局配置四位核心、六位周边居民，补职业、床位、活动地点和原生日程；有条件的旅人/商人另行出现。模板身份与 UUID 持久化，反复初始化不复制人口。所有具名友好人形可就近打字交谈，核心伙伴保留更深的长期记忆和任务权限。不能把“十人出生”解读成十人在同屏或十人同时请求模型。

原生住宅增加分层外观、窗灯和入屋淡化，真实 7×6 占地、门、床、脚点与投影共用元数据。修正初始动物阻挡第一处住宅的问题；出生从营地实际起点搜索连通干地、校验原生碰撞和人物占位。失败保留待生成人物并重试，不提前写成功标记。

继续使用已经接入的 AgentScope Java 2.0.4 和 AI Town 记忆/社交流程移植。新增统一 AiRequestScheduler，玩家对话优先，背景并发和请求预算受全局上限约束；远方居民低频模拟、未加载人物休眠。离线检查不调用付费模型。

## 光影、风动、水面和素材

- VisualMaterialDefinition 以实际 alpha 可见轮廓、脚点、目标高度、刚度和投影高度统一素材。六类地形 catalog 从 Mod JAR 的完整 classloader 路径读取；原生 ResourceEncoder 不收录 JSON，已用真实运行资源链回归。
- SDV-Radiance 移植新增近似表面法线、光源遮挡、接收面与半影。CPU 从自有素材轮廓/亮度烘焙法线，GLSL 2.1 兼容管线消费平行图集和局部高度/材质纹理。尚未移植完整多目标 reliefreplay、精确绘制顺序重放或水面真实反射，不宣称已经等同上游整套效果。
- Simple Wind Shader 2D 延续根部固定与高度权重，新增共享 WindField、稳定逐株相位和刚度；精灵与投影使用同一风动。石头/冰晶等刚性物关闭摆动。光源位置缓存与每帧火光强度分开，减少不同图层更新节奏错位。
- GDQuest water_2D 的连续 UV 扰动与水色思路移植到当前 shader，使用自有噪声/纹理，叠浅深水、岸边与投影。没有采用其非商用美术。
- 风、火光、水与荧光共享可暂停的视觉时间；荧光使用浮点上升、漂移、渐现渐隐和密度预算。性能段不截图或编码；录屏段单独采样，不能把截图读取造成的卡顿当作游戏帧率。
- 修正 NaturalPathRenderer 把连续世界宽度 0 当作越界的问题，负坐标与已加载道路恢复原圆润边缘；图集限制 4096 格、16 页，并保护当前及上一准备帧正在使用的槽位。
- 基于实际海岸昼夜帧回调配色：夜间保留植物绿色，深青绿环境与暖灯分开；昼间单独抑制荧黄高亮，不增加曝光。室内铺地与有效住宅占地上的野草、植物及投影同步排除。

来源及具体移植边界见 `mosslume/third-party/SDV-Radiance-surface/`、`simple-wind-2d/`、`gdquest-water/`，以及 `mod/resources/third-party/agentscope-java/` 和 `third-party/ai-town/`。没有通过安装一个整包替代本作素材、坐标或原生规则适配。

## 实际验收

以下结果保存于 `mosslume/validation/world-visuals-r6/`。离线测试、原生服务端检查、客户端区域请求和实际画面分别记录；物理鼠标/键盘未操作，不标记为通过。

| 检查 | 实际结果 |
| --- | --- |
| 统一构建与离线回归 | 35 项通过；含真正注入原生 ItemFinder 字节码并执行真实库存预留、住宅存档、生成、水文、缓存、风动和 AI 调度 |
| 四向探索与区域加载 | 四个方向跨旧边界，包含负坐标；服务端传送推动普通客户端请求/应用 3×3 区域，四次稳定样本一致后返回营地。不是物理走路测试 |
| 退出和重开 | 四处远区编辑经过进程退出与磁盘重开仍保留，再次卸载/加载成立；箱子、玩家库存、伙伴身份/记忆/任务恢复，洞穴往返通过 |
| 攻击 | 近战在进度 .4667 首次观察到实际伤害且只命中一次；远程只发一枚弹体；目标消失取消、目标离开范围不命中。未声称弹体最终落点/隔墙等所有战斗分支均完成 |
| 人口和交谈 | 实际 4 核心 + 6 居民、10 唯一 UUID、重试不复制、原生存档身份载荷一致；阿朔先走 28.2 px，交谈 5.0067 秒/101 次采样位移 0且全数面向玩家，退出后走 101.5 px，守卫指令保留 |
| 服务端继续推进 | 交互后 20 秒/401 ticks，最大 tick 间隔约 69.8 ms，正常保存；不是长时间稳定性结论 |
| 最终海岸画面 | 实际应用 2400×1800 昼夜帧；GPU 投影、海岸投影和风动启用，风动 fallback 0；原生客户端四方向攻击均有出手，9 次请求被接受 |
| 短时帧间隔 | 12.01 秒/713 个间隔，平均 59.47 fps，p95 21.17 ms、p99 28.70 ms、最大 48.02 ms，0 帧超过 50 ms；未达到 p95≤20 ms 目标 |

性能段没有 ReadPixels/PNG；该段窗口未获焦点，后台降帧设置已关闭，旧用户游戏仍在运行，不能据此声明同场景相对基线提升或所有场景稳定 60 fps。最终剪辑录得 135 帧/8.00 秒，按 `frames.csv` 的真实采样时间编码。录屏读取与编码影响采样密度，视频不是 60 fps 性能证据；前半夜晚、后半白天为诊断时间切换。录屏 PNG 从完整 Retina 帧最近邻采样为 1200×900，全分辨率静帧保持原样。

离线检查和本轮集成没有调用付费模型。AI SDK 和既有记忆方案保留，本次没有以模型回复代替原生执行。

已定位的中间失败均发生在隔离 QA 资料目录：显示器休眠导致 GLFW 无活动显示器；原生资源索引过滤 JSON；测试把 Mob.ai 清空；聊天测试位置未同步到客户端。这些分别修正后才继续对应检查，未结束旧版玩家进程。

## 仍需继续的内容

精确复刻参考视频仍需要连续画面对照。完整四向怪物动作、部分职业行走/眨眼、复杂建筑室内外、所有地形长时间探索和完整 PRD 的任务/内容回归不因本轮代码接入自动完成。本轮帧时间样本只能代表测量场景及当时机器负载，不能推出所有场景稳定 60 fps。
